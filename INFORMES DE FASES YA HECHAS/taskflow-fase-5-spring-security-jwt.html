🏗️ ¿Qué se construyó en esta fase?

Se agregó autenticación y autorización completa a TaskFlow. Hasta la Fase 4 cualquier persona podía acceder a todos los endpoints sin identificarse. 📚 Conceptos Aplicados — Tutorial

1. Spring Security — ¿Qué es?

Spring Security es el framework de seguridad estándar para aplicaciones Spring. Funciona como una cadena de filtros HTTP que intercepta cada request antes de que llegue al controller. En Spring Boot 3+/4 se configura con SecurityFilterChain en lugar del antiguo WebSecurityConfigurerAdapter.

// SecurityConfig.java — reglas de acceso por URL
@Bean
public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
    http
        .csrf(AbstractHttpConfigurer::disable)  // JWT es stateless, no necesita CSRF
        .authorizeHttpRequests(auth -> auth
            .requestMatchers("/auth/**").permitAll()          // público
            .requestMatchers("/swagger-ui/**").permitAll()    // público
            .requestMatchers("/actuator/health").permitAll()  // público
            .requestMatchers(HttpMethod.DELETE, "/api/tareas/**").hasRole("ADMIN")
            .anyRequest().authenticated()                     // resto requiere token
        )
        .sessionManagement(s ->
            s.sessionCreationPolicy(SessionCreationPolicy.STATELESS)) // sin sesiones
        .addFilterBefore(jwtAuthFilter,
            UsernamePasswordAuthenticationFilter.class);
    return http.build();
}

2. JWT — JSON Web Token

JWT es un estándar (RFC 7519) para transmitir información de forma segura como un objeto JSON firmado. Es stateless: el servidor no guarda estado de sesión, toda la información necesaria está dentro del token.

Estructura de un JWT:

eyJhbGciOiJIUzM4NCJ9          ← HEADER  (algoritmo: HS384)
.eyJyb2wiOiJST0xFX1VTRVIi... ← PAYLOAD (email, rol, expiración)
.spbsgbe3JcA6B1_n56m27UQ...  ← SIGNATURE (HMAC firmado con clave secreta)
// JwtService.java — generación del token
public String generarToken(UserDetails userDetails) {
    Map<String, Object> claims = new HashMap<>();
    claims.put("rol", userDetails.getAuthorities()
            .stream().findFirst()
            .map(Object::toString).orElse("ROLE_USER"));

    return Jwts.builder()
            .claims(claims)
            .subject(userDetails.getUsername())    // email del usuario
            .issuedAt(new Date())                  // cuándo se emitió
            .expiration(new Date(
                System.currentTimeMillis() + jwtExpiration)) // expira en 24h
            .signWith(getSigningKey())              // firma con HMAC-SHA
            .compact();
}

// Validación del token
public boolean esTokenValido(String token, UserDetails userDetails) {
    final String email = extraerEmail(token);
    return email.equals(userDetails.getUsername()) && !estaExpirado(token);
}

3. BCrypt — Hash seguro de contraseñas

BCrypt es un algoritmo de hash unidireccional diseñado específicamente para contraseñas. Es lento por diseño (factor de costo configurable), resistente a ataques de fuerza bruta. Genera un salt aleatorio por cada hash — dos passwords iguales dan hashes distintos. Es unidireccional — nunca se puede revertir al texto original.

// SecurityConfig.java
@Bean
public PasswordEncoder passwordEncoder() {
    return new BCryptPasswordEncoder(); // factor de costo 10 por defecto (~100ms/hash)
}

// AuthController.java — registro con hash
UserEntity usuario = new UserEntity(
    request.nombre(),
    request.email(),
    passwordEncoder.encode(request.password()), // NUNCA texto plano
    UserEntity.Rol.USER
);

4. UserDetails y UserDetailsService

Spring Security necesita un contrato estándar para representar al usuario autenticado. UserDetails es la interfaz que define ese contrato. Al implementarla en UserEntity, nuestra entidad JPA se convierte directamente en el objeto de seguridad sin clases intermedias.

// UserEntity.java — implementa UserDetails
@Entity
@Table(name = "users")
public class UserEntity implements UserDetails {

    @Enumerated(EnumType.STRING)
    private Rol rol;  // USER o ADMIN

    public enum Rol { USER, ADMIN }

    @Override
    public Collection<? extends GrantedAuthority> getAuthorities() {
        return List.of(new SimpleGrantedAuthority("ROLE_" + rol.name()));
        // Rol.ADMIN → "ROLE_ADMIN" | Rol.USER → "ROLE_USER"
    }

    @Override
    public String getUsername() { return email; } // usamos email como username
}

// UserDetailsServiceImpl.java — carga usuario desde BD
@Service
public class UserDetailsServiceImpl implements UserDetailsService {
    @Override
    public UserDetails loadUserByUsername(String email) {
        return userRepository.findByEmail(email)
            .orElseThrow(() -> new UsernameNotFoundException(
                "Usuario no encontrado: " + email));
    }
}

5. JwtAuthenticationFilter — Interceptor de requests

Este filtro se ejecuta en cada request HTTP antes de que llegue al controller. Extiende OncePerRequestFilter — garantiza ejecución exactamente una vez por request. Extrae el token del header Authorization: Bearer <token>, lo valida y registra al usuario en el SecurityContext.

@Component
public class JwtAuthenticationFilter extends OncePerRequestFilter {
    @Override
    protected void doFilterInternal(HttpServletRequest request,
            HttpServletResponse response, FilterChain filterChain) {

        final String authHeader = request.getHeader("Authorization");

        // Sin token → continuar sin autenticar (llegará al 401)
        if (authHeader == null || !authHeader.startsWith("Bearer ")) {
            filterChain.doFilter(request, response);
            return;
        }

        final String jwt = authHeader.substring(7); // quitar "Bearer "
        final String email = jwtService.extraerEmail(jwt);

        if (email != null &&
            SecurityContextHolder.getContext().getAuthentication() == null) {
            UserDetails userDetails = userDetailsService.loadUserByUsername(email);
            if (jwtService.esTokenValido(jwt, userDetails)) {
                // Token válido → usuario autenticado para este request
                UsernamePasswordAuthenticationToken authToken =
                    new UsernamePasswordAuthenticationToken(
                        userDetails, null, userDetails.getAuthorities());
                SecurityContextHolder.getContext().setAuthentication(authToken);
            }
        }
        filterChain.doFilter(request, response);
    }
}

6. AuthController — Registro y Login

Endpoints públicos — no requieren token. El registro hashea la contraseña con BCrypt antes de guardarla. El login usa AuthenticationManager para verificar credenciales contra la BD + BCrypt automáticamente.

// POST /auth/register → 201 Created + JWT
@PostMapping("/register")
public ResponseEntity<AuthResponse> register(@Valid @RequestBody RegisterRequest request) {
    if (userRepository.findByEmail(request.email()).isPresent()) {
        return ResponseEntity.status(HttpStatus.CONFLICT).build(); // 409
    }
    UserEntity usuario = new UserEntity(
        request.nombre(), request.email(),
        passwordEncoder.encode(request.password()), // BCrypt hash
        UserEntity.Rol.USER
    );
    userRepository.save(usuario);
    String token = jwtService.generarToken(usuario);
    return ResponseEntity.status(HttpStatus.CREATED)
        .body(AuthResponse.of(token, usuario.getEmail(),
              usuario.getRol().name(), 86400000L));
}

// POST /auth/login → 200 OK + JWT
@PostMapping("/login")
public ResponseEntity<AuthResponse> login(@Valid @RequestBody LoginRequest request) {
    Authentication auth = authenticationManager.authenticate(
        new UsernamePasswordAuthenticationToken(request.email(), request.password()));
    UserEntity usuario = (UserEntity) auth.getPrincipal();
    String token = jwtService.generarToken(usuario);
    return ResponseEntity.ok(AuthResponse.of(token, usuario.getEmail(),
           usuario.getRol().name(), 86400000L));
}

8. Manejo de errores 401 y 403

// SecurityConfig.java — respuestas JSON personalizadas
.exceptionHandling(ex -> ex
    .authenticationEntryPoint((request, response, e) -> {
        // Sin token o token inválido → 401
        response.setStatus(401);
        response.setContentType("application/json;charset=UTF-8");
        response.getWriter().write(
            "{\"status\":401,\"error\":\"No autenticado\"," +
            "\"mensaje\":\"Se requiere token JWT.\"}");
    })
    .accessDeniedHandler((request, response, e) -> {
        // Token válido pero sin el rol necesario → 403
        response.setStatus(403);
        response.setContentType("application/json;charset=UTF-8");
        response.getWriter().write(
            "{\"status\":403,\"error\":\"Acceso denegado\"," +
            "\"mensaje\":\"No tienes permisos para esta operación\"}");
    })
)

🔗 Relaciones entre Conceptos

SecurityFilterChain→JwtAuthenticationFilter: el filtro JWT se agrega con addFilterBefore(), ejecutándose antes que el filtro estándar de usuario/contraseña.
JwtAuthenticationFilter→JwtService: el filtro delega en JwtService para extraer el email y validar la firma del token en cada request.
JwtService→application.yml: la clave secreta y el tiempo de expiración se inyectan con @Value desde la configuración centralizada.
UserDetailsService→UserRepository: Spring Security llama a loadUserByUsername() que consulta la BD por email (Fase 4).
UserEntity→UserDetails: al implementar UserDetails, la entidad JPA se integra directamente con Spring Security sin clases intermedias.
BCryptPasswordEncoder→DaoAuthenticationProvider: el proveedor usa BCrypt para comparar el password del request contra el hash guardado en BD.
Flyway V3→UserEntity: la migración añade las columnas password y rol que JPA mapea en la entidad.
