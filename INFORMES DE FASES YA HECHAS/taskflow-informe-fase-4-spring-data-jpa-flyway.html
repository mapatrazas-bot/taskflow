🏗️ ¿Qué se construyó en esta fase?

Se agregó la capa de persistencia real a TaskFlow. Hasta la Fase 3 los datos vivían en memoria (un List<Task>). En esta fase conectamos la aplicación a una base de datos real usando Spring Data JPA con Hibernate como ORM, H2 como BD en memoria para desarrollo y Flyway para gestionar las migraciones SQL de forma versionada.

📚 Conceptos Aplicados — Tutorial

1. JPA y Hibernate — ¿Qué son?

JPA (Jakarta Persistence API) es una especificación de Java que define cómo mapear clases Java a tablas de base de datos. Hibernate es la implementación más popular de JPA. Spring Boot lo configura automáticamente con spring-boot-starter-data-jpa.

Entidad JPA — TaskEntity.java

@Entity                          // Marca la clase como entidad JPA (tabla en BD)
@Table(name = "tasks")           // Nombre exacto de la tabla en la BD
@EntityListeners(AuditingEntityListener.class)  // Activa auditoría automática
public class TaskEntity {

    @Id
    @GeneratedValue(strategy = GenerationType.SEQUENCE, generator = "tasks_gen")
    @SequenceGenerator(name = "tasks_gen", sequenceName = "tasks_seq", allocationSize = 1)
    private Long id;

    @Column(nullable = false, length = 100)
    private String titulo;

    @Enumerated(EnumType.STRING)    // Guarda "PENDIENTE" en lugar de 0, 1, 2
    private TaskStatus status;

    @ManyToOne(fetch = FetchType.LAZY)  // Muchas tareas → 1 usuario (LAZY = eficiente)
    @JoinColumn(name = "usuario_id")
    private UserEntity usuario;

    @CreatedDate                   // Spring pone la fecha automáticamente al insertar
    @Column(name = "fecha_creacion", updatable = false)
    private LocalDateTime fechaCreacion;

    @LastModifiedDate              // Se actualiza automáticamente al modificar
    private LocalDateTime fechaActualizacion;
}

2. Flyway — Migraciones Versionadas

Flyway gestiona cambios de esquema de BD de forma controlada. Cada cambio es un script SQL con nombre versionado (V1__descripcion.sql). Flyway lleva un historial en la tabla flyway_schema_history y garantiza que cada script se ejecute exactamente una vez.

V1__crear_tablas.sql

  • CREATE TABLE users
  • CREATE TABLE tasks
  • Índices de rendimiento
  • Secuencias para IDs

V2__datos_iniciales.sql

  • INSERT usuario: Ana García
  • INSERT 5 tareas de prueba
  • Datos para desarrollo local
  • Se ejecuta solo en H2
⚠️ Nota técnica Spring Boot 4.x: La autoconfiguration de Flyway en Spring Boot 4.1.1 no se activa correctamente cuando el datasource está en un perfil separado. La solución aplicada fue registrar Flyway como @Bean manual en AppConfig.java con initMethod = "migrate", lo que garantiza su ejecución independientemente del perfil.

3. Spring Data JPA — Repositorios

JpaRepository elimina el código boilerplate de CRUD. Spring Data genera automáticamente las implementaciones de los métodos basándose en los nombres de los métodos (derived query methods). 
public interface TaskRepository extends
        JpaRepository<TaskEntity, Long>,      // CRUD + paginación gratis
        JpaSpecificationExecutor<TaskEntity> { // filtros dinámicos

    // Método derivado — Spring genera el SQL automáticamente
    List<TaskEntity> findByUsuarioIdAndStatus(Long usuarioId, TaskStatus status);

    // JPQL — consulta orientada a objetos (no SQL)
    @Query("SELECT t FROM TaskEntity t WHERE t.usuario.id = :uid ORDER BY t.fechaCreacion DESC")
    List<TaskEntity> buscarPorUsuarioOrdenado(@Param("uid") Long usuarioId);

    // Proyección — solo devuelve titulo y status (más eficiente)
    List<TareaResumen> findByUsuarioId(Long usuarioId);
}

4. @Transactional — Gestión de Transacciones

@Transactional garantiza que un conjunto de operaciones en la BD se ejecute como una unidad atómica: todo se confirma o todo se revierte si hay error. 
@Service
@Transactional(readOnly = true)   // Optimización: todas las ops son solo lectura por defecto
public class TaskJpaService {

    @Transactional               // Sobreescribe el readOnly para escrituras
    public TaskEntity crear(TaskEntity tarea) {
        return taskRepository.save(tarea);
    }

    // Paginación real con Spring Data
    public Page<TaskEntity> listar(Pageable pageable) {
        return taskRepository.findAll(pageable);
    }
}

5. Specification — Filtros Dinámicos

Specification permite construir consultas SQL dinámicas en tiempo de ejecución. En lugar de tener un método por cada combinación de filtros, usamos predicados combinables. 
public class TaskSpecification {
    public static Specification<TaskEntity> conStatus(TaskStatus status) {
        return (root, query, cb) ->
            status == null ? null : cb.equal(root.get("status"), status);
    }
    // Se combina en el servicio:
    // Specification.where(conStatus(s)).and(conPrioridad(p)).and(conCategoria(c))
}

6. Auditoría JPA — @CreatedDate / @LastModifiedDate

Con @EnableJpaAuditing en la configuración y @EntityListeners(AuditingEntityListener.class) en la entidad, Spring Data pobla automáticamente los campos fechaCreacion y fechaActualizacion sin código adicional.

🔗 Relaciones entre Conceptos

Flyway → Hibernate: Flyway crea las tablas ANTES de que Hibernate intente usarlas. Por eso ddl-auto: none — le decimos a Hibernate que NO toque el esquema.

@Entity → Repository: El repositorio opera sobre entidades JPA. Spring Data genera el SQL basándose en las anotaciones de la entidad.

@EnableJpaAuditing → @CreatedDate: Sin @EnableJpaAuditing en AppConfig, las anotaciones de auditoría no se activan y los campos quedan vacíos.

Specification → JpaSpecificationExecutor: El repositorio debe extender JpaSpecificationExecutor para aceptar predicados dinámicos.

@Transactional(readOnly=true) → rendimiento: Hibernate optimiza las consultas de solo lectura omitiendo el dirty-checking, reduciendo el uso de memoria.
