📚 Conceptos Aplicados — Tutorial

1. Maven Lifecycle & Fat JAR

Maven gestiona el ciclo de vida del proyecto mediante fases estándar (compile → test → package). Con el plugin spring-boot-maven-plugin, la fase package genera un Fat JAR (o Uber JAR) que incluye las clases compiladas y todas las dependencias embebidas junto con Tomcat.

2. Docker Multi-Stage Build

El enfoque multi-etapa divide la creación de la imagen en dos entornos aislados:

1
Stage 1 (Builder - eclipse-temurin:21-jdk-alpine) Descarga dependencias Maven en capa cacheada y compila el Fat JAR mediante ./mvnw clean package -DskipTests.
2
Stage 2 (Runtime - eclipse-temurin:21-jre-alpine) Solo copia el artefacto app.jar generado. Crea un usuario no-root appuser por seguridad y define límites de memoria JVM con JAVA_OPTS.
3. Orquestación con Docker Compose

Define una red privada virtual (taskflow-network) donde la API resuelve a la base de datos por su nombre de servicio postgres-db:5432. Implementa un healthcheck mediante pg_isready para garantizar que PostgreSQL esté listo antes de arrancar la aplicación Spring Boot.

4. Automatización CI/CD con GitHub Actions

El archivo .github/workflows/ci.yml ejecuta en cada push y pull request sobre la rama main un runner Ubuntu con Java 21 Temurin, ejecutando los 35 tests automatizados y validando la construcción de la imagen Docker.

⚠️ Hallazgo Técnico Crítico y Solución

Problema: SchemaManagementException: missing table [tasks] en arranque PostgreSQL

En el perfil de producción inicial se definió ddl-auto: validate. Al arrancar un contenedor nuevo de PostgreSQL vacío, Hibernate ejecutó la validación del esquema antes de que Flyway aplicara las migraciones SQL (V1__crear_tablas.sql), causando que el contenedor de la aplicación fallara y entrara en bucle de reinicio.

Solución: Otorgar control exclusivo del esquema a Flyway con ddl-auto: none

Se modificó spring.jpa.hibernate.ddl-auto=none en application-prod.yml. De este modo, Flyway ejecuta las migraciones V1, V2 y V3 de forma atómica y ordenada al inicio, garantizando la creación de tablas, índices y secuencias sin colisión con Hibernate.

🔗 Relación entre los Conceptos Aplicados

Maven Wrapper (mvnw)
→
Garantiza reproducibilidad idéntica tanto en local, como dentro del contenedor Docker y en el runner de GitHub Actions sin requerir Maven preinstalado.
Multi-Stage Dockerfile
→
Aísla el código fuente y el compilador JDK en la etapa builder, entregando una imagen final en base a JRE Alpine ligera y sin herramientas innecesarias.
Docker Compose Healthcheck
→
Garantiza que PostgreSQL acepte conexiones de red antes de que Spring Boot arranque, sincronizando el orden de inicialización con Flyway.
Spring Profile prod
→
Inyecta dinámicamente las credenciales de PostgreSQL y el secreto JWT mediante variables de entorno en el contenedor.
