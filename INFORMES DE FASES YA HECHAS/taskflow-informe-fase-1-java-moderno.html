🎯 ¿Qué es TaskFlow?
TaskFlow es una API REST para gestión de tareas personales/laborales. Permite crear, actualizar y eliminar tareas con estados, prioridades, categorías y fechas límite. Incluirá autenticación JWT, documentación Swagger, base de datos PostgreSQL, tests, Docker, AWS y Kubernetes.

En la Fase 1 construimos el modelo de dominio puro en Java, sin Spring ni base de datos. Esto permite enfocarse en los fundamentos del lenguaje antes de añadir el framework.

1. POO — Clases, Herencia y Polimorfismo
BaseEntity → Task, User · método abstracto · toString() polimórfico

¿Qué es? La Programación Orientada a Objetos organiza el código en clases que encapsulan datos (campos) y comportamiento (métodos). La herencia permite que una clase hijo reutilice el código de una clase padre.

¿Dónde se aplicó? BaseEntity es la clase base abstracta. Task y User la extienden y heredan automáticamente id, fechaCreacion y fechaActualizacion sin duplicar código.

Polimorfismo: getDescripcionCorta() está declarado abstract en BaseEntity, cada subclase da su propia implementación. El mismo método, distinto comportamiento.

// BaseEntity — clase abstracta (padre)
public abstract class BaseEntity {
    private final Long id;
    private final LocalDateTime fechaCreacion;

    protected BaseEntity() {
        this.id = CONTADOR_ID.getAndIncrement();
        this.fechaCreacion = LocalDateTime.now();
    }
    // Obliga a cada subclase a implementar su descripción
    public abstract String getDescripcionCorta();
}

// Task hereda de BaseEntity — reutiliza id y fechas
public class Task extends BaseEntity {
    public String getDescripcionCorta() {
        return "Task[" + getId() + "] '" + titulo + "'";
    }
}

// User también hereda — misma firma, distinto resultado (polimorfismo)
public class User extends BaseEntity {
    public String getDescripcionCorta() {
        return "User[" + getId() + "] '" + nombre + "'";
    }
}

2. Enums con comportamiento
TaskStatus · Priority · Category — campos, constructores, métodos

¿Qué es? Un enum en Java no es solo una lista de constantes. Puede tener campos, constructores y métodos como cualquier clase, lo que permite encapsular lógica relacionada con cada valor.

¿Dónde se aplicó? TaskStatus sabe si permite modificaciones (isActivo()). Priority tiene nivel numérico para comparar y ordenar. Ambos tienen métodos de búsqueda con Optional.

public enum TaskStatus {
    // Cada constante tiene sus propios valores de campos
    PENDIENTE("Pendiente", true),
    COMPLETADA("Completada", false);   // estado final

    private final String etiqueta;
    private final boolean activo;

    TaskStatus(String etiqueta, boolean activo) {
        this.etiqueta = etiqueta;
        this.activo = activo;
    }

    // Método de negocio: ¿se puede cambiar desde este estado?
    public boolean isActivo() { return activo; }

    // Retorna Optional en lugar de null — más seguro
    public static Optional<TaskStatus> desdeCadena(String nombre) {
        for (TaskStatus s : values()) {
            if (s.name().equalsIgnoreCase(nombre)) return Optional.of(s);
        }
        return Optional.empty();
    }
}

3. Records (Java 16+)
TaskFilter · PageResult<T> · TaskStats — datos inmutables sin boilerplate

¿Qué es? Un record es una clase inmutable especial de Java 16+. El compilador genera automáticamente: constructor canónico, getters, equals(), hashCode() y toString(). No hay setters porque los records no mutan.

¿Por qué usarlo? Un filtro de búsqueda o un resultado de estadísticas son datos de entrada o salida puros, no necesitan mutar. Los records eliminan todo el código repetitivo.

¿Dónde se aplicó? TaskFilter encapsula criterios de búsqueda. PageResult<T> es genérico y calcula metadatos de paginación. TaskStats tiene un factory method con Streams.

// Declaración — el compilador genera TODO lo demás
public record TaskFilter(
    Optional<TaskStatus> status,
    Optional<Priority>   prioridad,
    Optional<Category>   categoria,
    Optional<String>     textoBusqueda
) {
    // Método estático — factory method
    public static TaskFilter sinFiltros() {
        return new TaskFilter(
            Optional.empty(), Optional.empty(),
            Optional.empty(), Optional.empty());
    }

    // Evalúa si una tarea cumple todos los criterios activos
    public boolean coincide(Task tarea) {
        return status.map(s -> tarea.getStatus() == s).orElse(true)
            && prioridad.map(p -> tarea.getPrioridad() == p).orElse(true)
            && categoria.map(c -> tarea.getCategoria() == c).orElse(true);
    }
}

// Record genérico — <T> puede ser Task, User, etc.
public record PageResult<T>(
    List<T> contenido, int paginaActual,
    int tamanioPagina, long totalElementos
) {
    public int totalPaginas() {
        return (int) Math.ceil((double) totalElementos / tamanioPagina);
    }
}

4. Generics
Filterable<T,F> · Sortable<T> · PageResult<T> · Map<Long,Task>

¿Qué es? Los Generics permiten escribir clases y métodos que funcionen con cualquier tipo, evitando duplicación y garantizando type-safety en tiempo de compilación.

¿Dónde se aplicó? La interfaz Filterable<T,F> acepta cualquier tipo de elemento T y cualquier tipo de filtro F. PageResult<T> pagina cualquier tipo de objeto. El Map<Long,Task> en TaskService garantiza que solo almacenamos Task.

// Interface genérica — T=tipo elemento, F=tipo filtro
public interface Filterable<T, F> {
    List<T> filtrar(List<T> elementos, F filtro);

    // default method que reutiliza filtrar()
    default List<T> filtrarYOrdenar(
            List<T> elementos, F filtro, Comparator<T> orden) {
        return filtrar(elementos, filtro)
            .stream().sorted(orden).collect(Collectors.toList());
    }
}

// TaskService: T=Task, F=TaskFilter
public class TaskService
    implements Filterable<Task, TaskFilter>, Sortable<Task> {

    // Map tipado — solo acepta Long como clave y Task como valor
    private final Map<Long, Task> tareas = new HashMap<>();
}

5. Collections
HashMap · ArrayList · List.of() · Collections.unmodifiableList()

¿Qué es? El framework de Collections de Java provee estructuras de datos reutilizables y optimizadas: List (ordenada), Map (clave-valor), Set (sin duplicados).

¿Dónde se aplicó? HashMap<Long,Task> como almacén en memoria en TaskService. ArrayList<Task> en User para las tareas del usuario. Collections.unmodifiableList() para exponer listas sin permitir modificación externa.

// HashMap como "base de datos" en memoria
private final Map<Long, Task> tareas = new HashMap<>();

// ArrayList interno — mutable
private final List<Task> tareas = new ArrayList<>();

// Exposición segura — lista no modificable (encapsulamiento)
public List<Task> getTareas() {
    return Collections.unmodifiableList(tareas);
}

// List.of() — lista inmutable literal (Java 9+)
List.of(t1, t2, t3).forEach(ana::agregarTarea);

6. Streams y Lambdas
filter · map · sorted · groupingBy · count · anyMatch · toList()

¿Qué es? La API de Streams (Java 8+) permite procesar colecciones de forma declarativa y funcional, encadenando operaciones sin bucles explícitos. Las Lambdas son funciones anónimas que se pasan como argumentos.

¿Dónde se aplicó? En TaskService para filtrar, ordenar, agrupar y contar tareas. En User para consultar tareas activas. En TaskStats para calcular estadísticas.

// filter + map + toList — filtrar y transformar
List<String> titulos = servicio.listarTodas().stream()
    .filter(t -> t.getCategoria() == Category.TRABAJO)  // lambda
    .map(Task::getTitulo)                                // method reference
    .toList();                                           // Java 16+

// groupingBy + counting — agrupar y contar
Map<Category, Long> conteo = tareas.values().stream()
    .collect(Collectors.groupingBy(
        Task::getCategoria,     // criterio de agrupación
        Collectors.counting()   // operación de agregación
    ));

// sorted con Comparator lambda — orden descendente por nivel
List<Task> porPrioridad = tareas.stream()
    .sorted(Comparator.comparingInt(t -> -t.getPrioridad().getNivel()))
    .collect(Collectors.toList());

// anyMatch — shortcircuit, para en el primer match
boolean hayUrgentes = tareas.stream()
    .anyMatch(t -> t.getPrioridad().esUrgente());

// skip + limit — paginación sobre un Stream
List<Task> pagina = todasFiltradas.stream()
    .skip((long) pagina * tamanio)
    .limit(tamanio)
    .collect(Collectors.toList());

7. Optional
buscarPorId() · getFechaLimite() · Optional.map().orElse() — null safety

¿Qué es? Optional<T> es un contenedor que puede tener un valor o estar vacío. Reemplaza el uso de null como señal de "ausencia de valor", forzando al llamador a manejar explícitamente ambos casos.

¿Por qué importa? El NullPointerException es el error más común en Java. Optional lo elimina al nivel de la API: si el método retorna Optional, es imposible olvidarse de manejar el caso vacío.

// buscarPorId retorna Optional — nunca null
public Optional<Task> buscarPorId(Long id) {
    return Optional.ofNullable(tareas.get(id));
}

// ifPresent — ejecutar solo si hay valor
servicio.buscarPorId(t1.getId())
    .ifPresent(t -> System.out.println(t.getTitulo()));

// ifPresentOrElse — manejar ambos casos
servicio.buscarPorId(999L)
    .ifPresentOrElse(
        t  -> System.out.println("Encontrada: " + t.getTitulo()),
        ()  -> System.out.println("No encontrada")
    );

// map + orElse — transformar si existe, o valor por defecto
String titulo = servicio.buscarPorId(id)
    .map(Task::getTitulo)
    .orElse("Sin título");

// orElseThrow — fallar rápido con excepción contextual
Task tarea = buscarPorId(id)
    .orElseThrow(() -> new TaskNotFoundException(id));

// Campo opcional en modelo — fecha límite puede no existir
public Optional<LocalDate> getFechaLimite() {
    return Optional.ofNullable(fechaLimite);
}

8. Excepciones personalizadas
ApiException → TaskNotFoundException, TaskValidationException, TaskStateException

¿Qué es? Las excepciones personalizadas crean una jerarquía propia del dominio, con mensajes y códigos de error específicos. Permiten distinguir entre "tarea no encontrada", "validación fallida" y "transición inválida" con catch separados.

Checked vs Unchecked: checked (extends Exception) obliga al llamador a declarar throws o usar try/catch. unchecked (extends RuntimeException) no obliga. Aquí usamos unchecked para errores de dominio.

// ApiException — raíz abstracta unchecked
public abstract class ApiException extends RuntimeException {
    private final String codigoError;
    private final int httpStatus;
    // ... (guardamos el código HTTP para usarlo en Fase 3 con Spring)
}

// TaskStateException — transición inválida entre estados
public class TaskStateException extends ApiException {
    public TaskStateException(TaskStatus actual, TaskStatus intentado) {
        super("No se puede cambiar de '" + actual.getEtiqueta()
            + "' a '" + intentado.getEtiqueta() + "'",
            "TASK_STATE_ERROR", 409);
    }
}

// Uso — transición inválida lanza excepción
try {
    tarea.cambiarStatus(TaskStatus.COMPLETADA);   // ok
    tarea.cambiarStatus(TaskStatus.EN_PROGRESO);  // lanza TaskStateException
} catch (TaskStateException e) {
    System.out.println(e.getCodigoError() + " | HTTP: " + e.getHttpStatus());
}

9. Interfaces y Polimorfismo
Filterable<T,F> · Sortable<T> — contratos, default methods, implementación múltiple

¿Qué es? Una interfaz define un contrato: qué debe hacer una clase, sin decir cómo. Una clase puede implementar múltiples interfaces (a diferencia de la herencia simple de clases). Los default methods (Java 8+) permiten añadir implementaciones concretas a interfaces.

// Filterable — contrato genérico con default method
public interface Filterable<T, F> {
    List<T> filtrar(List<T> elementos, F filtro); // abstracto

    // default method: implementación base que usa filtrar()
    default List<T> filtrarYOrdenar(
            List<T> elementos, F filtro, Comparator<T> orden) {
        return filtrar(elementos, filtro)
            .stream().sorted(orden).collect(Collectors.toList());
    }
}

// TaskService implementa DOS interfaces (polimorfismo múltiple)
public class TaskService
    implements Filterable<Task, TaskFilter>,
               Sortable<Task> {

    @Override
    public List<Task> filtrar(List<Task> elementos, TaskFilter filtro) {
        return elementos.stream()
            .filter(filtro::coincide)  // method reference al record
            .collect(Collectors.toList());
    }

    @Override
    public List<Task> ordenarPorPrioridad(List<Task> elementos) {
        return elementos.stream()
            .sorted(Comparator.comparingInt(t -> -t.getPrioridad().getNivel()))
            .collect(Collectors.toList());
    }
}

10. Fecha y Hora — java.time API
LocalDate · LocalDateTime · ChronoUnit · DateTimeFormatter

¿Qué es? La API java.time (Java 8+) reemplaza las antiguas clases Date y Calendar. Es inmutable, thread-safe y mucho más expresiva. LocalDate es solo fecha (sin hora), LocalDateTime incluye fecha y hora sin zona horaria.

// LocalDate — solo fecha (sin hora), ideal para fechas límite
private LocalDate fechaLimite;

// Comparar con la fecha de hoy
public boolean estaVencida() {
    return fechaLimite != null
        && fechaLimite.isBefore(LocalDate.now())
        && status.isActivo();
}

// ChronoUnit — diferencia en días entre dos fechas
public long diasRestantes() {
    return ChronoUnit.DAYS.between(LocalDate.now(), fechaLimite);
}

// LocalDateTime — fecha + hora para auditoría
private final LocalDateTime fechaCreacion = LocalDateTime.now();

// DateTimeFormatter — formatear para mostrar al usuario
private static final DateTimeFormatter FMT =
    DateTimeFormatter.ofPattern("dd/MM/yyyy HH:mm:ss");
String texto = fechaCreacion.format(FMT);  // "26/08/2025 14:30:00"

11. Manejo de Archivos — NIO2
Files · Path · Paths · BufferedWriter · try-with-resources

¿Qué es? La API NIO2 (java.nio.file, Java 7+) es la forma moderna de trabajar con archivos en Java. Reemplaza la antigua java.io.File. El patrón try-with-resources garantiza que los recursos (archivos, conexiones) se cierren automáticamente.

// Crear directorio y archivo si no existen (NIO2)
Path archivoLog = Paths.get("logs", "taskflow.log");
Files.createDirectories(archivoLog.getParent()); // crea logs/
if (!Files.exists(archivoLog)) Files.createFile(archivoLog);

// try-with-resources — cierre automático garantizado
// El compilador inserta el close() aunque haya excepción
try (BufferedWriter writer =
        new BufferedWriter(new FileWriter(archivoLog.toFile(), true))) {
    writer.write(contenido); // true = append, no sobreescribe
} // writer.close() se llama aquí automáticamente

// Leer todas las líneas (Java 11+)
List<String> lineas = Files.readAllLines(archivoLog, StandardCharsets.UTF_8);

// Sobreescribir archivo (limpiar log)
Files.writeString(archivoLog, "");

var · toList() · text blocks · switch expressions · AtomicLong

¿Qué incluye? Java 21 acumula muchas mejoras desde Java 8. En este proyecto usamos las más relevantes para código limpio y expresivo.

// var — inferencia de tipo local (Java 10+)
var resultado = servicio.buscarPorId(999L);   // Optional<Task>

13. Buenas prácticas
SOLID · Clean Code · Encapsulamiento · Inmutabilidad · Javadoc
  • Single Responsibility (SOLID-S): TaskService solo maneja lógica de tareas, TaskFileLogger solo escribe al log, DateTimeUtils solo formatea fechas.
  • Open/Closed (SOLID-O): Filterable<T,F> permite añadir nuevos tipos filtrables sin modificar la interfaz.
  • Encapsulamiento: todos los campos son private. Los setters validan antes de asignar. Los getters de colecciones retornan vistas inmutables.
  • Inmutabilidad: Records, List.of(), Collections.unmodifiableList().
  • Fail-fast: validamos al principio de cada método y lanzamos excepción inmediatamente si los datos son inválidos.
  • No null: usamos Optional en lugar de retornar null. Los constructores validan parámetros obligatorios.
  • Javadoc: todos los métodos públicos tienen documentación con @param, @return y explicación del concepto aplicado.
