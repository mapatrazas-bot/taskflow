⚙️ TaskFlow — Guía de configuración en IntelliJ IDEA

Solución definitiva para ejecutar un proyecto Spring Initializr con estructura Maven en IntelliJ · Fase 1

🔍 ¿Por qué ocurrió el problema?

Cuando se descarga un proyecto de Spring Initializr y se abre en IntelliJ, el ZIP contiene una carpeta interna con el mismo nombre del proyecto. Al extraerlo en una carpeta taskflow/, la estructura real queda en taskflow/taskflow/ — dos niveles. IntelliJ abre la carpeta externa como workspace, pero el módulo Maven real está un nivel más adentro. Esto hace que los archivos Java creados en el nivel externo no sean reconocidos por Maven y el botón ▶ Run nunca se habilita.

taskflow/ ← carpeta donde extrajiste el ZIP ├── src/ ← ❌ nivel incorrecto (sin pom.xml) │ └── main/java/com/taskflow/ └── taskflow/ ← ✅ módulo Maven real ├── pom.xml ← aquí está el pom.xml ├── .mvn/ └── src/main/java/ ← los archivos deben estar aquí
✅ Solución paso a paso
1
Abrir IntelliJ apuntando a la carpeta correcta

Al abrir el proyecto, seleccionar la carpeta interna (la que contiene el pom.xml), no la carpeta externa donde se extrajo el ZIP.

⚠️ Error frecuente: abrir Curso de java/taskflow/ en lugar de Curso de java/taskflow/taskflow/
2
Crear los archivos Java en la ruta correcta del módulo Maven

Todos los paquetes y archivos .java deben crearse dentro de:

taskflow\src\main\java\com\taskflow\

Comando PowerShell para crear la estructura completa:

# Ejecutar desde la carpeta que contiene el pom.xml
New-Item -ItemType Directory -Force -Path "src\main\java\com\taskflow\domain\enums"
New-Item -ItemType Directory -Force -Path "src\main\java\com\taskflow\domain\model"
New-Item -ItemType Directory -Force -Path "src\main\java\com\taskflow\domain\record"
New-Item -ItemType Directory -Force -Path "src\main\java\com\taskflow\domain\exception"
New-Item -ItemType Directory -Force -Path "src\main\java\com\taskflow\service"
New-Item -ItemType Directory -Force -Path "src\main\java\com\taskflow\util"
3
Registrar el pom.xml como proyecto Maven

Si IntelliJ no reconoce el módulo automáticamente:

→ Clic derecho sobre pom.xml → "Add as Maven Project"

Esperar a que la barra inferior diga "Resolving dependencies..." y termine.

ℹ️ Esto descarga todas las dependencias de Spring Boot (~100MB). Requiere internet y puede tardar 2-5 minutos la primera vez.
4
Verificar que los archivos quedan bajo el módulo Maven

En el panel de IntelliJ, los archivos deben verse con iconos de colores (no grises):

ÍconoTipoSignifica
🔵 CClassClase reconocida por Maven ✅
🟣 EEnumEnum reconocido ✅
🟡 ⚡ExceptionExcepción reconocida ✅
🔵 RRecordRecord reconocido ✅
🟢 IInterfaceInterfaz reconocida ✅
⬜ archivoFileNo reconocido por Maven ❌
5
Ejecutar con el triángulo verde ▶

Abrir TaskflowApplication.java → aparece el triángulo ▶ en el margen izquierdo junto al main() → clic → Run 'TaskflowApplication'

✅ Si ves el triángulo verde, Maven reconoce el archivo correctamente.
6
Si el triángulo no aparece — crear Run Configuration manual

Menú superior → flecha ▶ → Edit Configurations → + → Application

CampoValor
NameTaskflowApplication
SDKtemurin-21 (o el JDK 21 que tengas)
Main classcom.taskflow.TaskflowApplication
Moduletaskflow
⚠️ Si el buscador de Main class no encuentra la clase, primero registra el pom.xml como Maven Project (paso 3) y vuelve a intentarlo.
📁 Estructura final correcta del proyecto
taskflow/ ← workspace de IntelliJ └── taskflow/ ← módulo Maven (tiene pom.xml) ├── pom.xml ← ícono "m" azul en IntelliJ ├── mvnw / mvnw.cmd ├── .mvn/ └── src/ └── main/ ├── java/ │ └── com/taskflow/ ← todos los .java van aquí │ ├── domain/ │ │ ├── enums/ │ │ ├── exception/ │ │ ├── model/ │ │ └── record/ │ ├── service/ │ ├── util/ │ └── TaskflowApplication.java └── resources/ └── application.yaml
📄 ¿Para qué sirve application.yaml?

El application.yaml es el archivo de configuración de Spring Boot. En la Fase 1 no hacía nada porque desactivamos Spring (no llamamos a SpringApplication.run()). Solo tenía la línea que generó Spring Initializr automáticamente.

FaseQué se configura en application.yaml
Fase 1spring.application.name: taskflow — solo el nombre, sin efecto real
Fase 2Puerto del servidor, profiles activos (dev/prod)
Fase 3CORS, Actuator endpoints, logging
Fase 4DataSource (H2/PostgreSQL), JPA/Hibernate, H2 Console
Fase 5JWT secret, expiración de tokens
ℹ️ A partir de la Fase 2 volveremos a llamar SpringApplication.run(TaskflowApplication.class, args) y Spring leerá el application.yaml automáticamente al arrancar.
💡 Lección aprendida — para proyectos futuros

Cuando descargas un proyecto de start.spring.io:

A
Opción 1 — Extraer el ZIP y abrir la carpeta interna directamente

Extraer el ZIP → entrar a la carpeta interna que tiene el pom.xml → File → Open apuntando a ESA carpeta.

B
Opción 2 — Usar "Add as Maven Project" si ya abriste la carpeta externa

Clic derecho en el pom.xml interno → Add as Maven Project → crear todos los archivos dentro de taskflow/src/main/java/com/taskflow/
